# pricing-crosscheck

[![ci](https://github.com/abdulazizbalu/pricing-crosscheck/actions/workflows/ci.yml/badge.svg)](https://github.com/abdulazizbalu/pricing-crosscheck/actions/workflows/ci.yml)

A cross-validation harness for derivative pricing models.

This is not another pricing library or VaR engine. It checks independent
implementations of the same model against each other and against closed
forms, measures where and by how much they disagree, and explains why, with
a refinement or convergence experiment behind every explanation.

Phase 1 covers Black-Scholes-Merton dynamics: European, American,
single-barrier and cash-or-nothing digital options, priced by QuantLib's
analytic, binomial, finite-difference and Monte Carlo engines and by our own
NumPy references (closed forms, a CRR tree, a Crank-Nicolson PDE, a seeded
Monte Carlo).

## How it works

1. **Protocol first.** [docs/protocol.md](docs/protocol.md) fixed the
   instruments, grids, engine settings, references, tolerances, seeds and the
   rules for classifying disagreements before any result was generated. The
   numbers live in [specs/phase1.json](specs/phase1.json). Later changes are
   listed under "Deviations from protocol" with their reasons.
2. **References are validated before use.** Closed forms are tested against
   parities, limits, numerical integration and the Black-Scholes PDE; the
   tree, PDE and Monte Carlo must converge to the closed forms at their
   theoretical order (`tests/test_reference_*.py`). None of the reference code
   imports QuantLib.
3. **Every engine is compared with a reference it does not share code
   with**, on grids that include deep in/out of the money, one-day and
   ten-year maturities, sigma = 0.01 and 1.0, zero and negative rates and
   spot 0.1% from the barrier.
4. **Each disagreement is re-run at higher resolution** (2x and 4x steps or
   grid, 4x and 16x Monte Carlo samples) and classified by fixed rules.
5. **Identities** (put-call parity, in-out parity, digital call + put,
   American >= European, no early exercise) are checked per engine; identities
   that an engine satisfies by construction are labelled as carrying no
   information.

## Reproduce

Python 3.10 to 3.12 (committed results: CPython 3.12, linux-x86_64).
QuantLib 1.43 (pinned in `requirements.lock`; the version is checked at run
time and written into every results file).

```
python -m pip install --no-deps -r requirements.lock
python -m pip install --no-deps -e .
python -m pricing_crosscheck run --profile full --jobs 4
```

This regenerates `results/full/*.csv`, `results/full/summary.md`, the charts
in `docs/figures/` and the tables below. `--profile fast` runs the CI subset
(a few minutes). `python -m pricing_crosscheck check --profile fast`
regenerates and compares with the committed files. Every CSV starts with
comment lines holding the content hash and the exact library versions.

## Results (full grid)

The tables are generated from `results/full/summary.csv` and
`results/full/disagreements.csv`; counts are grid points. Tolerances: exact
class (QuantLib analytic engines) 1e-9; numerical class max(1e-5 x notional,
1e-4 x |reference|) with notional 100 (1 for digitals); Monte Carlo adds
4 standard errors. Full tables: [results/full/summary.md](results/full/summary.md).
The `not available` column counts every point without a usable value: engine
failures, expected payoff refusals (QuantLib CRR and MC on digitals) and
engines that do not price an instrument by design (`own_pde` knock-ins); the
status of each row is in `results/full/prices.csv`.

## Known limits

- Black-Scholes-Merton only in Phase 1: constant rate, dividend yield and
  volatility. No local or stochastic volatility, no discrete dividends.
- No market data and no calibration; all inputs are synthetic grid points.
- Results depend on the library versions, which are pinned and recorded in
  every results file. Another QuantLib version may give different numbers.
- The American reference is our own Crank-Nicolson PDE with a penalty
  method. Its time error is first order in practice; at points where its
  uncertainty estimate exceeds 0.1 x tolerance the point is excluded from the
  American comparison and counted as excluded.
- Barrier prices assume continuous monitoring and zero rebate.
- QuantLib engines are tested only through the Python wheel at the settings
  in the protocol; the findings describe observed behaviour and its likely
  numerical cause, backed by experiments. They are not claims about QuantLib
  source code.
- ORE (`open-source-risk-engine` 1.8.17.0) installs from PyPI but its
  engines for these products are QuantLib engines, so it is not used as an
  independent second engine in Phase 1.
